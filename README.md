# ai-teacher

把一篇文章自动变成一条带配音和代码演示的教学视频。自用工具，CLI 优先。

> 要接着往下开发，先看 [HANDOFF.md](HANDOFF.md) —— 那份写的是「现在到哪了、
> 接下来干什么、动手前必须知道的几条」。这份 README 讲的是设计与坑。

## 一句话流程

```
corpus/source.md      你的文章
      │
      ├─ pnpm plan         AI 写讲稿 + 分镜（带校验，不合格自动重试）
      ▼
corpus/episode.json   剧本：讲稿分段 + 画面配置
      │
      ├─ pnpm say          配音 + 词级时间戳
      ├─ pnpm storyboard   段号 → 真实时间（顺带切出字幕）
      └─ pnpm video        逐帧渲染 → 合成 mp4
      ▼
out/render/final.mp4
```

## 命令

| 命令 | 作用 | 耗时 |
|---|---|---|
| `pnpm plan [文章]` | AI 写剧本（默认读 `corpus/source.md`） | 1–4 分钟（含重试） |
| `pnpm say` | 生成配音 + 词级时间戳 | 30–60 秒 |
| `pnpm storyboard` | 把段号解析成真实时间 **+ 生成字幕** | 瞬间 |
| `pnpm dev` | 浏览器预览（**有声音**、可拖时间条、字幕可开关） | — |
| `pnpm video` | 一键出片（字幕烧进画面） | 3 分钟视频约 3.5 分钟 |
| `pnpm shot 20000` | 只截第 20000 毫秒那一帧（调试画面） | 几秒 |
| `pnpm shot:cue 3` | 截第 3 条字幕中间那一帧（**校对字幕最顺手**） | 几秒 |
| `pnpm typecheck` | 类型检查，应当是 0 错误 | 几秒 |

## 六条设计约束

**1. 画面 = 时间的纯函数。**
场景组件里**禁止** `setTimeout` / `setInterval` / CSS `transition` / `animation`。
所有视觉状态都由 `t`（毫秒）算出来。这样任意时刻都能「点名渲染」——
逐帧截图才有可复现性。

**2. 播放器可以用真实时间，场景不行。**
预览时以 `audio.currentTime` 为时钟（音画天然同步）；
出片时程序直接调 `window.__seek(t)`。边界就在这一层，别越界。

**3. audio-first：时长是从配音里量出来的，不是拍脑袋定的。**
换音色、改语速，帧数自动跟着变。画面迁就声音，不能反过来。

**4. 画面靠「段号」对齐，不靠名字。**（详见下一节）

**5. 每步产物落盘，改了什么只重跑那一步。**
改讲稿要重跑 `say`；只改画面不用重新配音。

**6. AI 的产出必须过校验才能进管线。**
不过校验就不覆盖 `episode.json`，并把问题清单喂回去让它自己改。

## 画面怎么和声音对齐（核心）

讲稿被切成一段一段（`parts`）。**每一段有一个段号，从 0 开始。**
画面元素写 `"part": 3`，意思就是「念到第 3 段的时候，这个元素出现」。

```json
{
  "parts": [
    { "text": "先说压缩，图片是页面体积的大头。" },
    { "text": "第一行，取出原图的宽和高。" }
  ],
  "scenes": [
    {
      "template": "CodeTyping",
      "startPart": 0,
      "props": {
        "fileName": "compress.js",
        "lines": [
          { "code": "const w = img.width, h = img.height", "part": 1 },
          { "code": "}" }
        ]
      }
    }
  ]
}
```

**为什么不用名字？** 一开始的做法是给段落起名字（`cue`），画面再引用那个名字。
结果是灾难：模型要同时维护两份清单，实测它的命名和顺序几乎每次都错，
而且错法五花八门（名字拼错、标了没人用、顺序颠倒、`startCue` 写成别的场景的）。
写了一堆校验规则也压不住 —— 因为**我们是在让模型做一件它不擅长的事**。

换成段号之后，那一整类错误**在结构上就不可能发生**：段号是程序数出来的，
模型只需要数对；顺序由「段号不能倒退」一条规则管住。

## 字幕怎么来的（`src/plan/subtitle.ts`）

字幕**不需要 AI 参与**，它是 `pnpm storyboard` 的副产物：

- **断句用讲稿原文** —— 词表里没有标点，拿它拼出来是一坨没有标点的字。
- **时间用词级时间戳** —— 但词级时间戳只给「每个词什么时候开始念」，
  一条字幕的结束时刻往往落在某个词念到一半的地方。所以要**插值出字级时间**：
  一个词读 350ms、有三个字，第 2 个字就落在 +117ms 附近。
- **段（`parts`）是不可跨越的边界** —— 一条字幕绝不跨段并排。
  段本来就是按语气切的，比任何启发式规则都靠谱。
- **断句顺序**：句号优先，逗号其次，都没有才硬切。
  第一版是「凑够 18 个字就切」，切出来是「…很简单， / 结果做出一条完整管线。这」
  —— 观众读到的永远是半句话。
- **一条字幕 = 一行**，字数上限（26 字）直接对齐「一行放得下多少字」。
  折行代码仍然留着（兜底），但正常不会再触发 —— 实测 39 条全部一行。
- **切点只落在词首**，绝不切在词中间。掩码标的是「字与字之间的缝」，
  和「第几个字符」差一格就会切出「六百五十|九KB」这种。
- **折行按词边界**，并按显示宽度挑最平衡的断点。
  只按字数切会切出「一百五十 / 四KB」「dataU / RL」这种。
- **代价**：为了守住「一行」，偶尔会切出偏短的一条（实测 3 条落在
  1.5~2.0 秒，最短 1.475 秒）。这是故意的取舍：切碎只是这一条短一点，
  折行则会让排版乱掉。

字幕是**时间的纯函数**（`Stage.vue` 里的 `Subtitle.vue` 那一层），
所以逐帧渲染天然带上它，不需要 ffmpeg 的 subtitles 滤镜，
也不需要额外跑一遍编码。

想改字幕，重跑 `pnpm storyboard` 就够了 —— 不用重新配音，也不用重新生成剧本。

## 踩过的坑（这些比代码值钱）

**渲染**

- **不能用 `file://` 打开构建产物。** 浏览器会以跨域为由拦掉 `<script type="module">`，
  页面根本不启动。必须在脚本里起一个本地静态服务器。
- **Playwright 自带的 ffmpeg 是精简版**，没有 mp4 封装器、没有 libx264，
  传 `-movflags` 直接报 `Unrecognized option`。装 `@ffmpeg-installer/ffmpeg`。
- **TTS 返回的词表里没有标点和空格。** 拿讲稿原文去比对永远对不上，
  两边都得先「只保留汉字/字母/数字」再比。
- **PowerShell 的 `Set-Location` 不改变 .NET 的工作目录。**
  用 `[System.IO.File]::WriteAllText()` 传相对路径会写到别的目录去。
  一定用绝对路径。
- **PowerShell 5.1 的 `-Encoding utf8` 会写 BOM。** ffmpeg 的 concat 列表、
  `.gitignore` 都会被 BOM 弄坏。
- **`Get-Content` 读无 BOM 的 UTF-8 会按 GBK 解**，中文注释会被写坏。
  用 `[System.Text.Encoding]::UTF8` 显式读。

**音画对齐**

- **要点/代码行的出现时机必须绑到某一段讲解上。** 没绑的元素会按固定间隔自己冒出来，
  而讲解早就讲到别处了。
- **场景不能挂太久。** 如果某几段讲解没有对应画面，上一个场景会一直挂在屏幕上 ——
  观众听到新话题、看到旧画面。这是「音画不同步」最常见的原因。
- **场景引用的段号不能越过下一个场景的开始**，否则那个元素永远不会出现。
- **「第一行/第二行」这类序号很脆弱。** 模型很容易从第 2 行开始数。
  改成直接描述这行在做什么更稳。

**字幕**

- **字坐标和原文下标是两套东西，混用必翻车。** 字坐标里没有标点（一个标点占 0 格），
  原文下标里标点占一格。「给博客加图片，本以为很简单，…」里第 22 个字
  在原文里是第 25 个字符。所有「边界对不对」的 bug 都是这两套坐标混了。
- **段边界绝不能用「时刻反推词边界」来算。** Edge 会把「管线。」和「这条管线…」
  并成同一个词条，用时刻一推就晚一个词 —— 于是每条字幕都多咬掉下一段的第一个字。
  要用**段的文字**去讲稿里顺序查找，得到确定的字符边界。
- **覆盖率检查抓不到「串位」。** 每个字都在，只是被划到了隔壁字幕 ——
  字数校验全过，画面却是半句话。所以还要单独校验「每个切点都在词首」。
- **标点必须显式归给左边那条字幕。** 边界正好落在标点之后时，
  这个标点谁都不认领（前一条切到标点前，后一条从标点后开始），
  画面上就是「结果做出一条完整管线」少个句号。
- **折行不能只按字符数。** 汉字和英文宽度不同（`canvas` 比同长度的汉字窄得多），
  而且按字符数切会把数词、英文单词劈开。要按显示宽度挑断点，且只在词边界断。
- **`pnpm shot:cue 3` 是校对字幕最快的路子** —— 直接截出第 3 条字幕的正中间那一帧。

**AI 生成**

- **提示词里写了却没校验的约束，等于没写。** 例如「全片不超过 900 字」——
  不加校验器，模型超了也没人管。
- **校验报错要翻译成「具体怎么改」。** 只说「找不到 cue」模型不知道该加还是该删；
  说清楚「要么补一段讲解，要么把这个字段删掉」它才改得对。
- **每一次翻车都应该变成一条机器能自动检查的规则。** 跑几轮之后，
  那一类错误就再也溜不到渲染阶段了。

## 渲染怎么提速的（静止帧复用）

先量，再动手：

| | 每帧耗时 |
|---|---|
| `page.screenshot()` | 78.9 ms |
| `page.evaluate(__seek)` | 13.4 ms |
| 内容与上一帧**完全相同**的帧 | **79%** |

截图占八成半，而八成的帧是在重复截同一张画面。所以提速的办法不是「截图更快」，
而是**根本不截图**：`frames.ts` 每帧先问一句 `window.__static(t)`，
回答「这张画面和上一帧一样」就把上一帧的 PNG 复制过来。

实测（全片 4869 帧）：

```
朴素版 8.49 分钟  →  优化版 3.17 分钟   （2.7 倍）
复用 2888 帧（59%），复用一帧只要 2.9ms，渲染一帧要 89.7ms
```

判据在 `Stage.vue` 里（画面是时间的纯函数，所以判据也是），只有两个条件：

1. 场景里没有元素正在动
2. 这一帧和上一帧**落在同一条字幕里**，且那条字幕已经淡入完

**为什么按元素而不是按场景**：一张幻灯片的动效可能持续 16 秒
（要点在不同时刻出现），但那 16 秒里 89% 的帧画面根本没变 ——
它们都在「上一条要点稳定了、下一条还没出现」的空档里。
按整个场景一刀切时复用率只有 17%。

**怎么确认它没把画面弄坏**：`FRAMES_NO_REUSE=1` 关掉复用跑一遍，
和开着跑一遍，逐帧比对 PNG 的 MD5 —— 必须完全一致。
实测全片 4869 帧全同。

**踩过的坑（都是实测踩出来的，不是想出来的）**

- **不要用硬链接。** 想的是「硬链接不复制数据，几乎不花时间」，
  实测恰好相反：在这种有几万个文件的目录里 `link()` 要 47ms/次，
  而 `copyFile()` 只要 1.5~6.5ms —— 复制快 7 倍以上。
  （另外 NTFS 单文件硬链接上限 1024，超了直接报错。）
- **判据不能写在「页面当前时刻」上再做决定。** `__static` 是时间的纯函数，
  要在 `__seek` **之前**问；先 seek 再问的话复用帧也白付 11ms 的 seek。
  反过来说，问的时候页面还停在上一帧，所以判据里**不能**读任何 DOM 状态。
- **代码场景干脆不参与复用。** 我给它写过判据（逐字打字区间 + 光标闪烁），
  但一直有边界漏洞：全片实测仍有 29 帧被误判成静态 ——
  而那些帧一旦被复制成上一帧，画面就卡住了。
  「第几个字符已经打出来」由 `Math.floor(elapsed / CHAR_MS)` 决定，
  用 storyboard 里的 `atMs` 去推总会差一两个字符。
  幻灯片没有这种自发动画，判起来可靠，所以只复用幻灯片。
- **对拍只能证明「没错」，不能证明「有效」。** 这个功能第一版复用率恒为 0%
  （因为判据问错了对象），而对拍照样全绿。
  所以两个都测：对拍查正确性，`__static` 命中率查有效性。

## 已知限制

- **渲染速度**：静止帧复用之后快了一倍多，但代码打字场景仍然复用不上，
  而它占本片约三分之一时长。再往下可做的：多场景并行渲染、
  换 CDP 截图绕开 Playwright 的封装。
- 画面类型只有两种：幻灯片、代码打字。
- 字幕只有中文、只有画面内烧录一种形式。没有单独的 `.srt` / `.vtt` 文件
  —— 想上传到 B 站/YouTube 用平台字幕的话，得从 `storyboard.json` 的 `cues` 导一份。
- 讲稿的语义正确性靠模型自觉，程序只能保证结构正确
  和「每行代码都有对应讲解」。
